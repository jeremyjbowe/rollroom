# Rollroom

A standard Next.js app for Vercel. The operator calculator is public. Exactly one administrator manages the shared product library at `/admin`, using username `admin` and a configured password. There is no registration, user database, or ChatGPT authentication.

## Vercel deployment

Import `jeremyjbowe/rollroom`, framework Next.js, Node 24. Connect a **private Vercel Blob** store. Set these server-only production environment variables:

- `BLOB_READ_WRITE_TOKEN`: provided by the connected private store.
- `ADMIN_PASSWORD_HASH`: scrypt hash generated by `pnpm admin:password` with a 16–256-character password supplied via stdin. Never store the plaintext password in Git or a public variable.
- `ADMIN_SESSION_SECRET`: at least 32 random bytes, encoded as hex or base64url.

Production must be publicly accessible in Vercel Deployment Protection so operators do not encounter Vercel sign-in. The application protects `/admin` and all product writes independently. Preview deployments have no admin credentials by default. Use a separate private store and separate secrets if enabling editing in previews.

## Admin access

Open `/admin`, enter username `admin` and the password. Sessions expire after eight hours. Sign out from Products. To rotate the password, generate a new hash, replace `ADMIN_PASSWORD_HASH` in Vercel, and redeploy; old sessions become invalid. Rotating `ADMIN_SESSION_SECRET` also invalidates sessions. There is no password reset endpoint or first-visitor administrator registration.

Login attempts are limited to ten per 15-minute window across the single account, using an atomic record in private storage. Passwords are salted and scrypt-hashed. Sessions use signed HS256 tokens, password-version binding, HttpOnly/Secure/SameSite=Strict cookies, and strict same-origin write checks. Authentication fails closed if configuration or storage is unavailable.

## Product storage

The library is a small private JSON document in Vercel Blob, capped at 1,000 products. Reads bypass Blob CDN caching. ETag-conditional writes with bounded retries prevent concurrent catalog changes from overwriting each other. Editing checks the product version to reject stale forms. Notes and archived products never appear in the public API. There is no reliance on Vercel function disk or memory for persistent data.

Keep face, adhesive and liner together when measuring total caliper. Record actual core outside diameter and measurement date. There are no assumed product presets.

## Local development and checks

Use Node 24 and pnpm 11.25.0. `pnpm install --frozen-lockfile`; copy `.env.example` to ignored `.env.local` and configure a dedicated test Blob store and admin secrets. Then `pnpm dev`.

- `pnpm test`: calculation, password/session, concurrency, stale edit, privacy and rate-limit tests.
- `pnpm typecheck`: TypeScript checks.
- `pnpm build`: standard Next.js production build; no live secrets are required at build time.

Do not connect local or preview tests to production data. Never commit `.env.local`, Vercel tokens or the administrator password.

## Calculation

Feet = π × (rollOD² − coreOD²) / (4 × thicknessMil / 1000) / 12. Diameters are normalized to inches. Buildup uses rollOD = coreOD + 2 × buildup. Usable feet subtract an explicit allowance, clamp to zero, and round down. A close fit means less than 10% of job footage or 5 ft of extra material, whichever is larger. This is an operational heuristic, not a confidence interval. Validate against known rolls before production use.

## Remnant inventory

`/inventory` is available without signing in. Operators can save remnants from the calculator or add them directly, record roll width in inches and estimated usable footage, choose a location/bin, update remaining footage after printing, and print a paper label with a stable roll ID. Search matches product, SKU, roll ID and bin; filters support location, minimum length, minimum width and status. The location filter is remembered on the station's browser.

The admin-only `/admin/locations` page manages locations. DTP St. George and DTP Vegas are the initial defaults. Locations with available rolls cannot be removed until those rolls are moved or removed. Location removal is reversible. Roll removal and “used up” are also reversible and retained in history; restoration requires confirming a currently active product, location and positive remaining footage.

Inventory is a separate private Blob document at `inventory/catalog.json`. Writes use conditional ETags and per-roll update timestamps to prevent overwriting another station's edits. Operators intentionally have anonymous read/write access to inventory; product and location changes still require the admin session. Origin checks reject cross-site browser submissions. Do not put confidential information in operator-visible notes. The current catalog supports up to 10,000 roll records (including history).

Labels print through the browser on ordinary paper and can also be saved as PDF in the print dialog. Reprint after changing footage. The application does not automatically subtract a print job: operators enter the remeasured usable length.
